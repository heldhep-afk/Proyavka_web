# Проявка — структурный отчёт по коду

Документ описывает, из чего состоит проект, что делает каждый блок файлов и как данные проходят через приложение. Номера строк указаны по текущей версии файлов (при правках они могут сдвигаться).

---

## 1. Общая картина

Проект — одностраничное приложение (SPA) без сборки, фреймворков и сервера.

- **Три раздела** (`Фото`, `Заказы`, `Кабинет`) — это три `<section>` на одной странице. Переключение идёт по `location.hash`, а видимостью управляет JavaScript.
- **Вся логика** — в одном файле `js/app.js` (769 строк), подключённом в конце `<body>`.
- **Все данные** (аккаунты, сеанс, заказы, библиотека эффектов) хранятся в `localStorage` браузера.
- **Фото обрабатывается на клиенте** через `<canvas>`: эффекты считаются попиксельно на JavaScript, готовый макет скачивается как JPEG.

### Как это работает по шагам

```
Пользователь выбирает файл
        │
        ▼
readFileAsDataUrl()  →  строка base64
        │
        ▼
loadImage()          →  объект Image
        │
        ▼
state.image          →  состояние редактора
        │
        ▼
renderEditor()  →  drawCanvas() + updatePrice()
        │
        ▼
<canvas id="cv">  →  то, что видит пользователь
        │
        ▼
«Заказать»  →  миниатюра + запись в localStorage  →  раздел «Заказы»
```

Ключевая идея архитектуры: **состояние (`state`) — единственный источник правды**. Любое действие пользователя меняет `state` и вызывает `renderEditor()`, а не правит картинку напрямую.

## 3. `index.html` — разметка (79 строк)

### 3.1. Голова документа (строки 1–9)

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

`viewport-fit=cover` нужен, чтобы на телефонах с «вырезом» страница занимала весь экран, а отступы под системные панели задавались в CSS через `env(safe-area-inset-*)`.

Здесь же подключаются шрифты и `css/style.css`.

### 3.2. Шапка (строки 11–14)

| Элемент | Назначение |
|---|---|
| `a.logo` | логотип «Проявка», внутри `span.reg` — три цветных круга |
| `nav` | ссылки на разделы; активная получает `aria-current="page"` |
| `#navCab` | третья ссылка: «Войти» для гостя или имя пользователя после входа |

Круги логотипа (`<i></i>` × 3) — не картинка, а три `div`-кружка, наложенных друг на друга с `mix-blend-mode`.

### 3.3. Раздел «Фото» (строки 17–51)

Каркас — сетка из двух колонок (`.grid`): слева предпросмотр, справа четыре блока настроек.

**Предпросмотр (строки 21–24)**

```html
<canvas id="cv" width="900" height="600" aria-label="Предпросмотр фото"></canvas>
<p class="empty" id="hint">Загрузите фото. Наклейки можно двигать мышкой.</p>
```

Атрибуты `width`/`height` — это внутреннее разрешение холста; на экране он растягивается по ширине колонки через CSS. `#hint` — подсказка, которая скрывается после загрузки первого фото.

**1. Фото (строки 26–27)** — `<input type="file" id="file" accept="image/*">`. Сам файл никуда не отправляется: он читается в браузере и превращается в `Image`.

**2. Эффект (строки 28–33)**

- `#fxBtns` — пустой контейнер, кнопки эффектов создаёт JS из объекта `EFFECTS`;

- `#ovFile` — загрузка своей PNG-рамки или текстуры;
- `#lib` — мини-библиотека сохранённых рамок пользователя.

**3. Наклейки (строки 34–38)**

- `#looks` — пустой контейнер: готовые образы и отдельные эмодзи-наклейки (заполняет JS);
- `#sz` — ползунок размера выбранной наклейки (8–70 %);
- `#delSt` / `#clrSt` — удалить одну наклейку или все.

**4. Заказ (строки 39–49)**

| Поле | Что делает |
|---|---|
| `#fmt` | формат печати; список тоже строит JS из `FORMATS` |
| `#frame` | рамка: без рамки / белая / полароид |

Множитель бумаги зашит прямо в `value` опций — поэтому в JS достаточно `Number($("#paper").value)`.

Почти пустая секция: `<div id="ordList">` заполняется функцией `renderOrders()`. Изначально секция скрыта атрибутом `hidden`.

Два блока, которые показываются по очереди:

## 4. `css/style.css` — оформление (365 строк)

Файл идёт сверху вниз от общего к частному.

### 4.1. Переменные и темы (строки 1–60)

```css
:root {
  --bg: #F1F0EA;   /* фон страницы */
  --sf: #fff;      /* поверхность карточек */
  --ink: #17202A;  /* основной текст */
  --mut: #5d6673;  /* второстепенный текст */
  --c: #0E8FA8;    /* акцент: голубой */
  --m: #D12E77;    /* акцент: малиновый (кнопка «Заказать») */
  --y: #F0BE1E;    /* акцент: жёлтый (статус заказа) */
  --ln: #d9d7cd;   /* линии и рамки */
  --on: #fff;      /* текст на акцентном фоне */
}
```

Смысл переменных: все цвета заданы в одном месте, поэтому тема меняется переопределением девяти значений.

- **строки 16–28** — автоматическая тёмная тема: срабатывает, только если система в тёмном режиме и пользователь вручную не выбрал светлую (`:root:not([data-theme="light"])`).
- **строки 30–40** — принудительная тёмная тема через `data-theme="dark"` на `<html>`.
- **строки 42–46** — `box-sizing: inherit` для всех элементов; сам `border-box` задан в `:root`, поэтому ширина карточек считается вместе с рамкой и отступами.
- **строки 52–60** — в тёмной теме круги логотипа переключаются с `multiply` на `screen`, иначе они «проваливаются» в тёмный фон.

### 4.2. Каркас страницы (строки 62–176)

| Блок | Что задаёт |
|---|---|
| `html` (62–64) | `scroll-padding-top` — чтобы якорные ссылки не заезжали под липкую шапку |
| `body` (66–71) | фон, цвет текста, базовый шрифт Onest 16 px |
| `header` (73–84) | липкая шапка (`sticky`), flex-строка с переносом |
| `.logo`, `.reg` (86–123) | логотип и три кружка: `position: absolute` + сдвиг через `left` |
| `nav` (125–142) | меню справа (`margin-left: auto`), активная ссылка — инверсия цветов |
| `main` (144–148) | контент по центру, максимум 1080 px |
| `h1`, `h2`, `.lead` (150–163) | типографика заголовков и подзаголовка |
| `.grid` (165–176) | две колонки `1.4fr / 1fr`; на экранах ≤ 760 px — одна колонка |

### 4.3. Компоненты (строки 178–334)

- **`.box`** — универсальная карточка: поверхность, рамка, радиус 12 px.
- **`canvas`** — 100 % ширины, `touch-action: none` (нужно для перетаскивания наклеек пальцем), `cursor: grab`.
- **`.row`** — flex-контейнер для группы кнопок с переносом.
- **`button` / `.btn`** — базовый вид кнопки, минимальная высота 40 px (удобно нажимать пальцем).
- **`button[aria-pressed="true"]`** — выбранный эффект: подсветка рамки. Состояние хранится в атрибуте, а не в отдельном классе.
- **`.main`** — главная кнопка (малиновая).
- **`:focus-visible`** — заметная рамка фокуса для навигации с клавиатуры.
- **поля ввода** (244–256) — единый вид для `select`, `input`, `textarea`.
- **`.ord`, `.ord img`, `.st`** — строка заказа: миниатюра, текст, статус-«таблетка» справа.
- **`.lib`, `.lib img`, `.lib b`** — библиотека эффектов: превью 64×64 и кнопка «×» в углу. Шахматный фон под прозрачным PNG сделан градиентом `repeating-conic-gradient`.

### 4.4. Уведомление и служебные правила (строки 336–351)

`#toast` — фиксированная «плашка» по центру снизу, изначально `display: none`; показывает её JS.

```css
[hidden] { display: none !important; }
```

Важное правило: оно позволяет скрывать секции и блоки атрибутом `hidden` из JS, не заводя отдельные классы.

### 4.5. Анимация (строки 353–365)

Круги логотипа разъезжаются при наведении. Всё спрятано в `@media (prefers-reduced-motion: no-preference)` — если пользователь просил систему уменьшить анимацию, движения не будет.

## 5. `js/app.js` — логика (769 строк)

Файл разбит на смысловые части, идущие примерно в порядке выполнения.

### 5.1. Утилиты (строки 1–57)

**`$` (строка 3)** — короткая обёртка над `document.querySelector`, чтобы не писать длинные вызовы.

**`storage` (5–31)** — безопасная обёртка над `localStorage`:

```js
get(key, fallback) {
  try {
    const raw = localStorage.getItem(key);
    return raw === null ? fallback : JSON.parse(raw);
  } catch (error) {
    return fallback;
  }
}
```

Зачем: `localStorage` может быть недоступен (приватный режим), а в значении может лежать битый JSON. В обоих случаях возвращается значение по умолчанию, и приложение не падает. `set()` возвращает `true/false` и сообщает пользователю, если память переполнена.

**`toast(text)` (33–41)** — показывает уведомление на 2,6 секунды. Таймер хранится в свойстве функции (`toast.timer`), поэтому новое сообщение сбрасывает предыдущее и не мигает.

**`clamp` (43–45)** — ограничивает число диапазоном: `Math.min(max, Math.max(min, value))`.

**`escapeHtml` (47–57)** — экранирует `& < > " '` перед вставкой текста в `innerHTML`. Защита от XSS: пользователь может ввести в комментарий к заказу HTML-тег, и он отобразится как текст, а не выполнится.

### 5.2. Константы и данные (59–136)

**Размеры и лимиты (59–67)** — вынесены в константы, чтобы не искать «магические числа» по коду:

| Константа | Значение | Смысл |
|---|---|---|
| `CANVAS_WIDTH` | 900 | ширина макета в пикселях |
| `LIBRARY_MAX_WIDTH` | 600 | до какой ширины сжимается своя рамка в библиотеке |
| `THUMB_WIDTH` | 240 | ширина миниатюры заказа |
| `JPEG_QUALITY_DOWNLOAD` | 0.92 | качество скачиваемого JPG |
| `JPEG_QUALITY_THUMB` | 0.6 | качество миниатюры (экономия места) |
| `MIN_PASSWORD_LENGTH` | 6 | минимальная длина пароля |
| `MAX_QTY` | 500 | максимум копий |
| `LOOK_STICKER_SCALE` | 0.45 | насколько уменьшать наклейки готового образа |
| `DEFAULT_STICKER_SIZE` | 0.18 | размер отдельной наклейки (доля ширины) |

**`FORMATS` (69–75)** — форматы печати: подпись, размеры в миллиметрах и базовая цена. Из этого массива строятся список форматов и расчёт цены, поэтому новый формат добавляется одной строкой.

**`saturationMatrix(value)` (77–81)** — строит цветовую матрицу 3×3, которая повышает или понижает насыщенность. Коэффициенты 0.213 / 0.715 / 0.072 — стандартные веса яркости для RGB. Используется эффектами «Ярче» и «Ретро».

**`EFFECTS` (83–112)** — словарь эффектов. Формат записи:

```js
bw: {
  name: "Ч/б",
  matrix: [...],   // как пересчитать цвет каждого пикселя
  contrast: 1.1,   // контраст
}
```

Эффект без `matrix` (например, `none`) ничего не меняет. Наличие `brightness` добавляет сдвиг яркости.

**`STICKERS` и `LOOKS` (114–136)** — набор эмодзи и готовые образы. Координаты в `LOOKS` заданы долями от ширины/высоты макета (0…1), чтобы образ выглядел одинаково на любом формате.

### 5.3. Состояние (138–156)

```js
const state = {
  image: null,        // загруженное фото
  imageVersion: 0,    // растёт при новой загрузке — сбрасывает кэш
  effect: "none",     // ключ из EFFECTS
  overlay: null,      // своя рамка/текстура
  vignette: false,
  stickers: [],       // [{ emoji, x, y, size }]
  selected: -1,       // индекс выбранной наклейки
  formatIndex: 0,     // индекс в FORMATS
  landscape: false,
  frame: "none",
};
```

Отдельные переменные рядом:

- `user` — текущий пользователь из `localStorage` или `null`;
- `filterCache` — кэш обработанного фото;
- `isRegisterMode` — форма открыта как регистрация, а не вход;
- `dragIndex` — какую наклейку сейчас тащат;
- `canvas` — ссылка на `<canvas id="cv">`.

### 5.4. Отрисовка макета (158–282)

**`getCanvasSize()` (158–164)** — считает размеры холста под формат. Ширина всегда 900 px, высота — по пропорции формата; при горизонтальной ориентации стороны меняются местами.

**`getFilteredImage(iw, ih)` (170–210)** — самая «тяжёлая» функция.

1. Сначала проверяется кэш по ключу «эффект + размер + версия фото». Если он совпадает, готовая картинка возвращается сразу — иначе при каждом движении мыши наклейки пересчитывали бы миллионы пикселей.
2. Фото вписывается в область по принципу `cover` (заполнить, обрезав лишнее) — отсюда `Math.max` в коэффициенте масштаба.
3. Затем идёт попиксельная обработка:

```js
for (let i = 0; i < pixels.length; i += 4) {
  const r = pixels[i];
  const g = pixels[i + 1];
  const b = pixels[i + 2];
  for (let channel = 0; channel < 3; channel++) {
    let value =
      r * matrix[channel * 3] +
      g * matrix[channel * 3 + 1] +
      b * matrix[channel * 3 + 2];
    value = (value - 128) * contrast + 128 + brightness;
    pixels[i + channel] = value < 0 ? 0 : value > 255 ? 255 : value;
  }
}
```

Шаг `i += 4` — потому что в данных пикселя четыре байта: R, G, B и прозрачность. Формула `(value - 128) * contrast + 128` усиливает контраст вокруг середины, не сдвигая общую яркость. Тернарный оператор в конце — ограничение значения диапазоном 0…255 (иначе браузер сам обрежет, но лучше явно).

**`drawCanvas(target)` (212–277)** — собирает макет слоями:

1. Белый фон.
2. Расчёт полей под рамку: у «Полароида» широкое нижнее поле (`0.16` ширины), у «Белой рамки» — равномерное `0.03`, без рамки — ноль.
3. Фото, к которому уже применён эффект.
4. Виньетка: радиальный градиент от прозрачного к тёмному, обрезанный по области фото (`clip`), чтобы не закрашивать поля.
5. Своя рамка/текстура поверх фото.
6. Наклейки: размер считается от ширины макета, поэтому эмодзи масштабируются вместе с ним. Выбранная наклейка обводится пунктиром.

Если фото ещё нет, вместо него рисуется серый прямоугольник-заглушка.

**`renderEditor()` (279–282)** — единая точка перерисовки: обновляет холст и цену. Именно её вызывают все обработчики.

### 5.5. Цена и построение интерфейса (284–314)

**`getQty()` (284–287)** — читает количество, ограничивает 1…500 и подставляет 1, если введено не число (например, пусто или буквы).

**`updatePrice()` (289–293)**:

```js
const basePrice = FORMATS[state.formatIndex].price;
const paperFactor = Number($("#paper").value) || 1;
$("#price").textContent = `${Math.round(basePrice * getQty() * paperFactor)} ₽`;
```

Цена = базовая цена формата × количество × множитель бумаги. `|| 1` защищает от `NaN`, если значение списка окажется пустым.

**Строки 295–314** — списки создаются из данных прямо в HTML-строки:

- формат — `new Option(...)` в `#fmt`;
- эффекты — кнопки с `data-fx="ключ"` и `aria-pressed`;
- образы — кнопки с `data-look="имя"`;
- наклейки — кнопки с `data-stk="эмодзи"`.

Так добавление нового эффекта в `EFFECTS` автоматически добавляет кнопку в интерфейс — правок в HTML не требуется.

### 5.6. Управление редактором (316–445)

**Выбор эффекта (316–324)** — обработчик на контейнере (`делегирование событий`): клик ловится на всём блоке, а нужный ключ берётся из `event.target.dataset.fx`. Так не нужно вешать отдельный обработчик на каждую кнопку. После смены эффекта обновляется `aria-pressed` и вызывается `renderEditor()`.

**`applyLook(name)` (326–337)** — ставит готовый образ: копирует список наклеек, переводит координаты `y` из долей высоты в общую систему (всё считается от ширины) и уменьшает размеры на `LOOK_STICKER_SCALE`.

**`addSticker(emoji)` (339–349)** — добавляет одну наклейку в центр и сразу выделяет её, а ползунок размера выставляет на значение по умолчанию.

**Строки 351–381** — добавление образов и наклеек, ползунок размера, удаление одной и всех наклеек. Везде одна схема: изменить `state` → `renderEditor()`.

**Строки 383–411** — поля заказа. `#fmt`, `#frame`, `#land` дополнительно вызывают `resetFilterCache()`, потому что при смене размера или рамки картинку нужно пересчитать заново. Количество и бумага влияют только на цену.

**Загрузка фото (413–445)**

```js
function loadImage(source) {
  return new Promise((resolve, reject) => {
    const image = new Image();
    image.onload = () => resolve(image);
    image.onerror = () => reject(new Error("Не получилось открыть фото"));
    image.src = source;
  });
}
```

`Image` загружается асинхронно, поэтому обёрнут в `Promise`: `await` ждёт окончания загрузки, а ошибка попадает в `catch`.

`readFileAsDataUrl(file)` (422–429) — то же самое для `FileReader`: файл превращается в строку `data:image/...;base64`.

Обработчик `#file` (431–445):

```js
state.image = await loadImage(await readFileAsDataUrl(file));
state.imageVersion += 1;   // кэш эффекта станет недействительным
resetFilterCache();
$("#hint").hidden = true;
renderEditor();
```

`imageVersion` — простой способ инвалидировать кэш: ключ кэша меняется, и старое фото не «прилипает» к новому.

Блок `finally { event.target.value = ""; }` очищает поле файла, чтобы можно было выбрать тот же самый файл повторно (иначе браузер не создаст событие `change`).

### 5.7. Перетаскивание наклеек (447–486)

**`pointerToCanvas(event)` (447–454)** — переводит координаты курсора в координаты холста:

```js
const rect = canvas.getBoundingClientRect();
const scale = canvas.width / rect.width;
return [
  ((event.clientX - rect.left) * scale) / canvas.width,
  ((event.clientY - rect.top) * scale) / canvas.width,
];
```

Холст на экране меньше своих 900 px, поэтому нужен коэффициент `scale`. На выходе — доли ширины (0…1), в той же системе, что и координаты наклеек.

**`pointerdown` (456–474)** — ищет ближайшую наклейку в радиусе `size * 0.6` (перебор с конца, чтобы верхняя наклейка перехватывала клик первой). Если попадание есть — запоминает индекс в `dragIndex`, выделяет наклейку и захватывает указатель через `setPointerCapture`, чтобы перетаскивание не прерывалось при выходе курсора за холст.

**`pointermove` (476–482)** — двигает выбранную наклейку и перерисовывает макет.

**`pointerup` (484–486)** — сбрасывает `dragIndex`.

Используются именно Pointer Events, а не `mousedown/mousemove`, потому что они одинаково работают с мышью, пальцем и стилусом.

### 5.8. Аккаунт (488–565)

**`hashPassword(password)` (488–496)** — считает SHA-256 через `crypto.subtle.digest` и возвращает hex-строку. Пароль в открытом виде не сохраняется. `crypto.subtle` работает только в защищённом контексте (HTTPS или `localhost`), поэтому при открытии файла напрямую показывается понятная ошибка.

**`clearAuthForm()` (498–502)** — очищает почту, пароль и имя. Нужна, чтобы пароль не оставался в поле после входа.

**`setAuthMode(register)` (504–511)** — переключает форму между входом и регистрацией: показывает поле имени, меняет заголовок, подписи кнопок и `autocomplete` пароля (`new-password` / `current-password` — подсказка менеджеру паролей).

**Обработчик `#authGo` (515–556)** — порядок проверок:

1. Формат почты регулярным выражением;
2. Длина пароля;
3. Хэширование (ошибка среды — в `toast`);
4. Чтение списка пользователей;
5. Регистрация (проверка занятости почты и наличия имени) **или** вход (сравнение хэшей).

```js
const storedHash = entry ? entry.hash || entry.h : "";
```

Совместимость со старыми записями: раньше поле называлось `h`, теперь `hash`; читаются оба варианта.

После успеха создаётся сеанс `user = { mail, name }`, сохраняется в `localStorage` под ключом `session`, форма сбрасывается и пользователь попадает в редактор.

**Выход (558–565)** — обнуляет `user`, удаляет `session`, чистит форму и открывает кабинет.

### 5.9. Библиотека эффектов (567–646)

- `libraryKey()` — ключ вида `fx:mail@example.com`, то есть у каждого пользователя своя библиотека.
- `getLibrary()` — читает массив и проверяет, что это действительно массив.
- `renderLibrary()` (577–590) — рисует превью с кнопкой «×»; один и тот же HTML вставляется в два места: в редактор (`#lib`) и в кабинет (`#lib2`).
- `#ovFile` (592–621) — своя рамка: применяется сразу, а если пользователь вошёл — уменьшается до 600 px по ширине и сохраняется в библиотеку. Миниатюра хранится как `data:image/png` (важно: PNG сохраняет прозрачность).
- Делегированный клик (623–646) — ловит нажатия на превью (`data-use`) и на «×» (`data-del`) во всех местах сразу, включая кабинет.

### 5.10. Заказы (648–705)

- `ordersKey()` — `orders:mail`, у каждого пользователя своя история.
- `nextOrderId()` (658–661) — берёт максимальный номер и прибавляет единицу; `|| 0` защищает от записей без номера, `1000` — нижняя граница нумерации.
- **`#send` (663–697)** — собирает объект заказа:

```js
const order = {
  id: nextOrderId(orders),
  date: new Date().toLocaleString("ru-RU"),
  fmt: FORMATS[state.formatIndex].label,
  paper: $("#paper").selectedOptions[0].text,
  qty: getQty(),
  recv: $("#recv").value,
  note: $("#note").value.trim(),
  sum: $("#price").textContent,
  fx: EFFECTS[state.effect].name,
  thumb: thumbnail.toDataURL("image/jpeg", JPEG_QUALITY_THUMB),
  status: "Принят",
};
```

Перед этим из холста делается миниатюра 240 px по ширине — полноразмерный макет в `localStorage` не поместился бы. `orders.unshift(order)` ставит новый заказ в начало списка.

- **`#dl` (699–705)** — скачивание: временная ссылка `<a download="maket.jpg">` с `href` из `canvas.toDataURL`. Такой приём работает без сервера.

### 5.11. Список заказов (707–739)

`renderOrders()` обрабатывает три случая: гость, пустая история, есть заказы.

```js
const thumbSource = order.thumb || order.th || "";
const thumb = /^data:image\//.test(thumbSource) ? thumbSource : "";
```

Две защиты:

1. `order.thumb || order.th` — совместимость со старыми заказами, где миниатюра называлась `th`;
2. проверка префикса `data:image/` — в `src` нельзя подставить произвольную строку (например, `javascript:`).

Все текстовые поля проходят через `escapeHtml`, поэтому HTML в комментарии к заказу не сломает разметку.

### 5.12. Маршруты и запуск (741–769)

```js
const ROUTES = ["editor", "orders", "cabinet"];

function renderRoute() {
  const requested = location.hash.slice(1);
  const route = ROUTES.includes(requested) ? requested : "editor";
  ...
}
```

Роутер без библиотеки:

1. Берёт `#hash` из адреса и проверяет, что это известный маршрут (иначе — редактор);
2. Скрывает все секции, кроме нужной, через атрибут `hidden`;
3. Помечает активную ссылку в меню `aria-current="page"`;
4. Обновляет шапку и кабинет под текущего пользователя;
5. Перерисовывает библиотеку, заказы и, если открыт редактор, макет.

В конце:

```js
addEventListener("hashchange", renderRoute);
renderRoute();
```

Слушатель реагирует на переходы по ссылкам, а прямой вызов нужен для первой загрузки страницы.

## 6. Что и где хранится в `localStorage`

| Ключ | Формат | Содержимое |
|---|---|---|
| `session` | `{ mail, name }` | кто сейчас вошёл |
| `users` | `{ "mail": { name, hash } }` | все аккаунты |
| `fx:mail` | `["data:image/png;...", ...]` | библиотека рамок и текстур |
| `orders:mail` | `[{ id, date, fmt, paper, qty, recv, note, sum, fx, thumb, status }]` | история заказов |

Почему так: у `localStorage` один общий набор ключей на сайт, поэтому данные пользователей разделены префиксом с почтой. Пароли хранятся только как хэш SHA-256.

## 7. Ограничения прототипа

1. **Аккаунты только на клиенте.** Всё лежит в браузере: данные не переживут очистку хранилища и не синхронизируются между устройствами. SHA-256 без соли — учебное упрощение, для реального продукта нужен сервер и медленное хэширование (bcrypt/argon2).
2. **Объём `localStorage` — около 5 МБ.** Поэтому миниатюры сжимаются до 240 px, а рамки — до 600 px. При переполнении появляется уведомление «Не сохранилось…».
3. **Вход работает только на HTTPS или `localhost`** — так устроен `crypto.subtle`. При открытии `index.html` двойным щелчком появится предупреждение.
4. **Эффекты считаются на CPU.** Большое фото и частые перерисовки могут подтормаживать; частично это решает кэш `filterCache`.
5. **Нет серверной валидации** — все проверки (почта, пароль, количество) выполняются в браузере и при необходимости обходятся.

## 8. Быстрая проверка работы

1. Открыть сайт через локальный сервер (`http://localhost:...`), а не как файл.
2. Загрузить фото → появляется макет, подсказка исчезает.
3. Переключить эффекты → картинка меняется, выбранная кнопка подсвечена.
4. Добавить образ и отдельную наклейку → перетащить мышью, изменить размер, удалить.
5. Сменить формат, рамку, ориентацию, бумагу и количество → макет и цена пересчитываются.
6. Зарегистрироваться → имя появляется в шапке, пароль из поля исчезает.
7. Нажать «Заказать» → заказ появляется в разделе «Заказы» с миниатюрой и статусом.
8. Нажать «Скачать фото» → сохраняется JPG.
9. Выйти → разделы «Заказы» и «Кабинет» снова просят войти.
